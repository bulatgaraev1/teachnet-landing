# CLAUDE.md

Рабочие заметки для Claude Code по этому репозиторию.

## Git-процесс
- Разработку вести в рабочей ветке `claude/...`, указанной в задаче; коммитить и пушить туда.
- **Всегда после пуша открывать pull request из рабочей ветки в `main`.**
  Если открытого PR для этой ветки ещё нет — создать новый; если он уже открыт —
  новые коммиты попадают в него автоматически (второй PR не нужен). Если предыдущий PR
  уже смержен, а на ветке появились новые коммиты — создать новый PR.
- **PR сразу вливать в `main` (squash) — указание владельца: «всегда вливай в main».**
  Не ждать отдельного подтверждения, если в задаче прямо не сказано «не мёржить» /
  «в main не мёржить до моей проверки». Перед вливанием — сборка и проверки зелёные.
- Деплой на reg.ru (FTPS) идёт из `main` через `.github/workflows/deploy.yml`,
  поэтому изменения видны на сайте только после мёрджа в `main`.

## Макеты — делать ровно по макету
- Если владелец дал макеты (HTML-файлы, картинки) — верстать их **такими, какие они есть**:
  те же блоки, тот же порядок, та же компоновка, те же тексты.
- Блоки со старых страниц сайта в такую страницу **не переносить** и ничего не подменять
  «по своим правилам» (свои цвета, фоны, фото, тексты, лишние секции).
- Если макет расходится с ТЗ, фактами или правилами сайта — не решать самому, а спросить владельца.
- Независимые блоки — есть на **любой** странице, даже если их нет в макете:
  cookie-плашка (`src/components/cookie-banner.ts`) и единый подвал сайта (`src/sections/footer.ts`).
- Бургер-меню и плавающую кнопку записи на лендинги вариантов главной (/education, /education2)
  добавлять, хотя в макетах их нет (решение владельца).

## Лендинги «Мастер-классы и значки» (/holiday/, /pcb/)
- Отдельное направление (пайка светящихся значков): статические страницы в `public/holiday/` и `public/pcb/`
  из архива владельца, всё описано в `docs/landings.md`, ТЗ — `docs/pcb/tz-claude-code.md`. Работа этапами.
- Школьное (`send.php`, `/dash`, счётчик Метрики 96429194, школьные документы ПДн) для них не трогать, и наоборот:
  у направления свои обработчик заявок, таблица, дашборд, счётчик, политика и согласие (`/pcb/privacy`, `/pcb/consent`).
- Шапка и подвал у них свои, из макета; единый подвал сайта и бургер сюда не добавлять. Плашка cookie — своя (`pcb/static/cookie.js`).
- Заявки: `public/pcb/lead.php` + `public/pcb/lib/pcb.php` → таблица `pcb_leads`, Telegram (тот же бот, **без контактов** — так написано
  в `/pcb/privacy`), письмо на pcb@. Вкладка дашборда — `/dash/?view=pcb` (`public/dash/pcb.php`, `pcb.js`), не отдельный адрес.
  Тесты — `tests/pcb/` (раздел 7 ТЗ, стенд — `tests/pcb/README.md`).

## Фото и логотипы
- Картинки лежат в `public/images/`. Серые `*.svg` там — заглушки.
- Чтобы поставить реальное фото/логотип, положить файл с тем же именем в растровом
  формате (`.webp` / `.jpg` / `.jpeg` / `.png`). Резолвер в `vite.config.ts` на сборке
  сам заменит ссылку `имя.svg` → `имя.<формат>` (приоритет: webp → jpg → jpeg → png).
  Код менять не нужно. Подробности и таблица имён/размеров — в README, раздел «📸 Фото».
- Не трогать: `logo-dark.svg`, `logo-white.svg`, favicon, og-image — они генерируются
  из `logo-full.svg` командой `npm run assets`.

## Служебные файлы в корне сайта — не удалять и не переименовывать
Лежат в `public/` и выкладываются в корень сайта при каждом деплое. Если файла не станет,
права в кабинете слетят (так уже было в 2024 году) или перестанет работать уведомление поисковиков.
- `yandex_f675b5659f3d4043.html` — подтверждение прав в Яндекс Вебмастере.
- `google5d36d0514a1b20e7.html` — подтверждение прав в Google Search Console.
- `BingSiteAuth.xml` — подтверждение прав в Bing Webmaster Tools.
- `b887174e966bb3311dbb16685f6fabe3.txt` — ключ IndexNow (его использует шаг IndexNow в деплое).
- `robots.txt`, `sitemap.xml`, `llms.txt`, `404.html` — тоже отсюда; новые страницы добавлять в `sitemap.xml`.
- `404.php` + `404-variants/` — страница «не найдено»: `.htaccess` (ErrorDocument 404/403) отдаёт `404.php`,
  он показывает случайный из шести вариантов (`404.html` и пять из `404-variants/`, витрина — `/404-variants/`).
  Варианты самодостаточные (без внешних ресурсов — CSP), ссылки в них только абсолютные.
