# Аналитика страницы /links (визитка для профиля соцсетей)

Счётчик Яндекс Метрики тот же — **96429194**. Все цели — тип **«JavaScript-событие»**
(в интерфейсе: «Целевое событие»), условие «Идентификатор цели» → **«совпадает»**.

Цели отправляются через обёртку `reachGoal()` (`src/lib/metrika.ts`): клики — атрибут `data-goal`
(обработчик `initGoalLinks()` из `src/lib/nav.ts`), заявка — общий компонент формы `src/components/form.ts`.

Ссылка для шапки профиля: `https://teachnet.ru/links?utm_source=instagram&utm_medium=social&utm_campaign=bio`
(для других соцсетей меняется `utm_source`: `vk`, `telegram` и т. д.).

## Заявка — существующая цель

| ID | Когда | Параметры |
|---|---|---|
| `lead_form` | заявка принята (ответ `send.php` 200) | `branch` — филиал, `source` = `links` |

Отдельно её создавать не нужно: это общая цель заявок сайта. Заявки с визитки отличаются параметром
`source = links`, в базе — `source = links`, в Telegram и письме — заголовком
«Новая заявка — визитка /links (из соцсетей)».

## Как устроено

- Ссылки внутри сайта (курсы, «Перейти на сайт», юридические страницы) уносят UTM текущего визита:
  метки из адреса `/links`, а если их там нет — сохранённые за визит (`src/lib/visit.ts`).
  Переход на главную или `/electronics` остаётся в той же рекламной кампании.
- Мессенджеры, телефон, филиалы и курсы берутся из `SITE` (`src/lib/site.ts`) и `EL_CONFIG`
  (`src/content/electronics.config.ts`), тексты страницы — `src/content/links.ts`.
- Составная цель «Воронка: нажали Записаться» (регулярное выражение `cta|^block4_signup$`)
  `links_signup_open` не засчитывает. Чтобы визитка попала в этот шаг воронки дашборда,
  в условие цели можно дописать `|^links_signup_open$`.
- Страница закрыта от поиска (`noindex, nofollow`) и не входит в `sitemap.xml`.
