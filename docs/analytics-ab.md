# A/B-тест главной: /education (B) и /education2 (C)

| Вариант | Адрес | Подача |
|---|---|---|
| A | https://teachnet.ru/ | текущая главная (не меняется) |
| B | https://teachnet.ru/education | «Сравнение»: многие кружки против TEACHNET, как проходит урок |
| C | https://teachnet.ru/education2 | «Манифест», тёмная подача |

Цена, оффер (бесплатный пробный урок), форма заявки и контакты на всех трёх одинаковые —
меняется только подача. Трафик между вариантами сайт не делит: в рекламе на каждый вариант
ведёт своя ссылка (свой адрес и свои UTM-метки).

Страницы B и C закрыты от поиска (`noindex, nofollow`, канонический адрес — главная),
в `sitemap.xml` их нет, в `robots.txt` они не закрыты (иначе поисковик не увидит `noindex`).

Счётчик Яндекс Метрики тот же — **96429194**. Цели — тип **«JavaScript-событие»**,
условие «Идентификатор цели» → **«совпадает»**.

## Блоки и форма

- **B:** шапка, первый экран, «Нас поддерживают» (строка логотипов), сравнение, урок, «Проверьте сами»,
  три ступени, мотивация, тёмный блок «Стоимость» с формой, вопросы, финал.
  В вопросах — два вопроса из макета и, как помечено в макете, остальные вопросы главной.
- **C:** шапка, манифест, лента фото, «Что мы видели», «Шесть правил», «Кто мы», «Проверьте нас»,
  светлый блок «Стоимость» с формой, финал.
- Независимые блоки сайта на обеих страницах: единый подвал (без колонки «Курсы»), cookie-плашка,
  а также бургер-меню и плавающая кнопка записи (решение владельца).
- Форма — компонент сайта (`src/components/form.ts`) в компоновке макета: подписи над полями,
  возраст 5–7 / 8–9 / 10–12 / 13–15 лет и филиал списками. Отправка, проверки, UTM, ClientID — как на главной.

## Параметр визита

При загрузке варианта уходит `ym(96429194, 'params', { ab_variant: 'b' })` или `'c'`.
На главной (вариант A) параметра нет.

## Заявки

- Форма — тот же компонент, что на главной, со скрытым полем `source`:
  `education` на /education, `education2` на /education2.
- В базе (`leads.source`) — `education` / `education2`.
- В Telegram и письме заголовок: «Заявка с главной — вариант B» / «Заявка с главной — вариант C».
- В дашборде /dash: источник «Главная — вариант B» / «Главная — вариант C»,
  в блоке «Какие страницы работают» — отдельные строки для /education и /education2.

## Как сравнивать варианты

1. **Конверсия в заявку.** Метрика → Отчёты → Конверсии, цель `lead_form`. Сегмент по странице входа:
   «Страница входа» = `https://teachnet.ru/`, `…/education`, `…/education2`. Или группировка
   по параметру визита `ab_variant` (у главной — «не определено»).
2. **Воронка.** Для каждого варианта: визиты → `scroll_price` / `scroll_conversion` →
   клик по кнопке записи (`hero_cta`, `nav_cta`, `sticky_cta`, `block12_cta`, на C ещё `c_dare_signup`) → `lead_form`.
   Составная цель «Воронка: нажали Записаться» (регулярное выражение `cta|^block4_signup$`)
   не считает `c_dare_signup`. Чтобы считала, в условие можно дописать `|^c_dare_signup$`.
3. **Глубина.** Сравнивайте общие цели прокрутки (`scroll_price`, `scroll_conversion`, `scroll_final`),
   а новые (`scroll_b_*`, `scroll_c_*`) смотрите как вовлечённость в свои блоки.
4. **Заявки по факту.** Дашборд /dash → «Что с заявками», колонка источника, или выгрузка из базы
   по `source`: `website` (A), `education` (B), `education2` (C).
5. Выводы делайте при сопоставимом трафике: одинаковые кампании и метки, не меньше 2 недель
   и не меньше ~30 заявок на вариант. Иначе разница может быть случайной.
